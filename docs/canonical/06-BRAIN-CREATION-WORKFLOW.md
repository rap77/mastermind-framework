# Brain Creation Workflow

## 1. Objetivo

Definir un proceso repetible para crear un nuevo brain desde cero, para cualquier nicho.

## 2. Workflow general

```text
Need Detected
→ Niche Framing
→ Gap Analysis
→ Brain Proposal
→ Expert Recommendation
→ Source Collection
→ Distillation
→ Brain Spec
→ Brain Validation
→ Runtime Registration
→ Experience Learning
```

## 3. Etapas

### 1. Need Detected

Definir por qué hace falta un nuevo brain.

### 2. Niche Framing

Aclarar nicho, límites, objetivos y contexto.

### 3. Gap Analysis

Decidir si hace falta un brain nuevo o si conviene extender uno existente.

### 4. Brain Proposal

Definir nombre, rol, inputs, outputs y límites.

### 5. Expert Recommendation

Seleccionar expertos relevantes y justificarlos.

### 6. Source Collection

Reunir corpus inicial de fuentes.

### 7. Distillation

Convertir fuentes en conocimiento operativo usable.

### 8. Brain Spec

Definir identidad, responsabilidad, anti-patrones y criterios.

### 9. Brain Validation

Validar utilidad, claridad de rol y no duplicación.

### 10. Runtime Registration

Registrar el brain en routing, config y runtime.

### 11. Experience Learning

Activar su memoria operativa futura.

## 4. Reglas de gobernanza

- no crear un brain nuevo si uno existente puede extenderse bien
- no elegir expertos solo por fama
- no integrar brains sin fuentes destiladas suficientes
- no mezclar doctrina base con experiencia temprana
- todo brain nuevo debe tener criterio de evaluación claro

## 5. Decisión estratégica

> La creación de brains debe ser un workflow de producto y conocimiento, no una tarea improvisada de prompts.
