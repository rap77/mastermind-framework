# 109. Phase 21.5 Evaluation Gate

## 1. Purpose

Define the operational gate for validating Brain #1 RAG before any scale-out.

The gate answers one question:

> Is Brain #1 RAG measurably good enough to move beyond the pilot?

## 2. Gate Inputs

- offline Recall@K evaluation output from `apps/api/mastermind_cli/rag/recall_eval.py`
- labeled evaluation pairs from `apps/api/tests/rag/fixtures/brain1_recall_pairs.json`
- cold-vs-RAG quality comparison scored by Brain #7
- contamination check results
- latency metadata already emitted by the coordinator

## 3. Gate Outputs

- `PASS` or `FAIL`
- recall report JSON
- quality comparison summary
- contamination summary
- final gate verdict artifact

## 4. Decision Rules

### Recall rule

- `recall_at_k` must be `>= 0.70`
- evaluation depth is `K=5` for the default gate run

### Quality rule

- Brain #7 must score the RAG run against the cold baseline
- the result must be explicitly recorded as a positive gate signal before scale-out

### Contamination rule

- the run must not re-use same-brain answers as retrieval targets
- any self-contamination check failure is an automatic `FAIL`

### Latency rule

- retrieval latency must remain within the Phase 21 budget defined in the execution plan
- the coordinator-sourced latency metadata is the source of truth for that check

## 5. Recommended Execution Order

1. run `recall_eval.py` for Brain #1 domain retrieval
   or execute the gate wrapper via `uv run python -m mastermind_cli.rag.gate`
   or `uv run python -m mastermind_cli.main eval rag-gate`
   or `./apps/api/scripts/rag-gate-smoke.sh`
2. compare RAG vs cold on the same labeled set (optional `--cold-output-path` + `--rag-output-path` on `rag-gate`)
3. run contamination checks (included in `rag-gate`)
4. record the final verdict

## 6. Exit Criteria

This gate is complete when:

- Recall@5 meets threshold
- quality comparison is recorded
- contamination is cleared
- latency budget is respected
- the verdict is persisted as the canonical gate outcome
