# Minimal Orchestration Path

## 1. Objetivo

Definir el flujo mínimo de orquestación que MasterMind debe ser capaz de ejecutar para considerarse usable en el MVP.

## 2. Principio central

> El flujo mínimo no debe intentar resolver todos los casos. Debe ser simple, trazable y reusable.

## 3. Capacidades mínimas del flujo

El camino mínimo debe permitir:

1. recibir un problema o brief
2. formularlo claramente
3. elegir brains relevantes
4. coordinar análisis multi-brain
5. registrar debate y decisión
6. definir gates
7. producir una salida accionable
8. guardar aprendizaje mínimo

## 4. Flujo mínimo

```text
Input
→ Problem Framing
→ Brain Selection
→ Parallel Analysis
→ Cross-Critique
→ Synthesis
→ Decision
→ Action Gating
→ Output
→ Learning Capture
```

## 5. Etapas mínimas

### A. Input

Puede ser:

- brief
- decisión a tomar
- problema técnico
- idea de producto
- solicitud de arquitectura

### B. Problem Framing

Transforma el input en:

- objetivo
- constraints
- criterios de éxito
- tipo de decisión

### C. Brain Selection

Selecciona el equipo mínimo necesario.

### D. Parallel Analysis

Cada brain produce análisis inicial independiente.

### E. Cross-Critique

Los brains objetan supuestos, riesgos o vacíos.

### F. Synthesis

Se integran acuerdos, desacuerdos y opciones.

### G. Decision

Se documenta ownership, rationale y estado.

### H. Action Gating

Se verifica si la acción puede ejecutarse.

### I. Output

La salida mínima debe ser uno de:

- decisión
- plan
- especificación
- recomendación
- bloqueo justificado

### J. Learning Capture

Se guarda aprendizaje mínimo reusable.

## 6. Output mínimo requerido

Todo flujo MVP debe producir al menos:

- problem statement
- participating brains
- main positions
- objections
- final decision
- required gates
- action / no-action status

## 7. Qué no debe intentar este flujo mínimo

- automatización total
- consenso perfecto
- cobertura de todos los nichos
- debate infinito
- resolución de toda ambigüedad posible

## 8. Casos ideales para probar este flujo

- una decisión de arquitectura
- una decisión de producto
- una decisión de riesgo / compliance
- un caso piloto finance/trading
- un proyecto externo pequeño

## 9. Criterio de éxito

El flujo mínimo es suficiente si:

- se puede repetir
- produce salidas útiles
- deja trazabilidad
- genera aprendizaje reusable

## 10. Decisión canónica

> El MVP de MasterMind debe apoyarse en un camino mínimo de orquestación simple y reusable, no en una orquestación total o perfecta.
