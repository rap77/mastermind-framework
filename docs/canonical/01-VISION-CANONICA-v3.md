# Vision Canónica v3

## 1. Qué es MasterMind

MasterMind es una plataforma para crear, orquestar y mejorar **cerebros especializados** capaces de operar sobre múltiples nichos, modelos y proyectos.

Combina:

- conocimiento destilado de expertos
- orquestación entre brains/agentes
- memoria de experiencia
- compatibilidad multi-LLM
- capacidad de crear nuevos brains para nuevos nichos

## 2. Tesis central

La calidad de un sistema agente mejora cuando no depende solo de un modelo generalista, sino de una arquitectura con:

- especialización disciplinaria
- conocimiento estructurado
- evaluación explícita
- memoria acumulada
- coordinación entre capacidades

## 3. Núcleo irrenunciable

El núcleo de MasterMind son los **brains**.

Cada brain debe tener:

- doctrina base
- fuentes expertas destiladas
- criterios de decisión
- anti-patrones
- rol claro dentro del sistema
- memoria operativa acumulada con el tiempo

## 4. Capacidades principales

### A. Brain Runtime

Usar brains existentes para resolver problemas reales.

### B. Brain Learning

Permitir que cada brain aprenda de experiencia validada.

### C. Brain Factory

Crear nuevos brains para nuevos nichos.

### D. Orchestration Layer

Coordinar brains, sintetizar outputs y evaluar calidad.

### E. Multi-LLM Layer

Ejecutar el sistema sobre múltiples proveedores y modos de acceso.

## 5. Cambio metodológico oficial

MasterMind adopta **Agent Skills** como metodología base.

### Decisión

- **GSD** queda como antecedente histórico
- **Agent Skills** pasa a ser la base operativa actual

### Razón

Porque encaja mejor con:

- spec-first
- SDD/spec-driven development
- workflows portables
- calidad de ejecución
- desarrollo agnóstico al runtime

## 6. Referencias externas

MasterMind absorbe patrones de otros sistemas, pero mantiene identidad propia.

### Paperclip

Referencia principal para:

- UX
- layouts
- experiencia operativa visual
- patrones de war room

### OpenClaw

Referencia secundaria para:

- routing
- runtime autónomo
- operación programática

### Hermes

Referencia externa principal para:

- memory
- MCP
- messaging gateway
- skills operativas
- runtime de agente más integrado

### Decisión

Hermes supera a OpenClaw como referencia principal para la evolución del runtime.

## 7. Compatibilidad multi-LLM

MasterMind debe ser **model-agnostic** y **provider-agnostic**.

### Debe soportar

- Claude
- Codex/OpenAI
- Gemini/Google
- OpenRouter
- otros proveedores futuros

### Debe soportar modos de acceso

- suscripción
- API key
- scheduling por costo/calidad/disponibilidad
- fallback automático entre proveedores

## 8. Aprendizaje por experiencia

Los brains deben ser **Experience-Augmented Brains**.

### Cada brain tiene dos memorias separadas

#### A. Domain Knowledge

Conocimiento experto destilado:

- libros
- papers
- artículos
- frameworks
- criterios
- anti-patrones

#### B. Experience Memory

Conocimiento operativo aprendido:

- decisiones pasadas
- resultados
- validaciones
- heurísticas
- errores repetidos
- patrones contextuales

### Regla crítica

La doctrina base y la memoria de experiencia no deben mezclarse sin control.

## 9. Qué significa aprender

Aprender no significa auto-reescribir libremente el brain.

Aprender significa:

- recordar qué funcionó
- evitar errores previos
- reutilizar heurísticas validadas
- adaptar recomendaciones según contexto
- mejorar con experiencia acumulada

### Regla

Solo debe consolidarse aprendizaje:

- validado
- trazable
- contextualizado
- preferiblemente evaluado por Brain #7

## 10. Creación de nuevos brains

MasterMind no solo debe usar brains existentes. También debe poder **crear nuevos brains para cualquier nicho**.

### El proceso debe incluir

- descubrimiento del nicho
- diseño de topología de brains
- recomendación de expertos
- recolección de fuentes
- destilación
- especificación del brain
- validación
- integración al runtime

### Nombre de esta capacidad

**Brain Factory** o **Brain Foundry**

## 11. Expert Recommendation Engine

MasterMind debe contar con un motor formal para recomendar expertos por brain y por nicho.

No debe optimizar por fama, sino por:

- relevancia
- operatividad
- complementariedad
- calidad de fuentes
- aplicabilidad contextual

## 12. Distillation Pipeline

MasterMind debe contar con un pipeline formal de destilación.

La destilación debe producir:

- principios
- frameworks
- criterios de decisión
- anti-patrones
- heurísticas
- artefactos estructurados reutilizables

No debe producir solo resúmenes.

## 13. Arquitectura conceptual objetivo

### Capa 1 — Expert Base

Fuentes maestras y conocimiento destilado

### Capa 2 — Brain Identity

Rol, doctrina, límites, criterios, anti-patrones

### Capa 3 — Orchestration

Routing, coordinación, síntesis, evaluación

### Capa 4 — Experience Memory

Memoria operativa por brain y por proyecto

### Capa 5 — Runtime Layer

Agent Skills + runtime inspirado en Hermes + MCP + multi-backend + interfaces

### Capa 6 — Brain Factory

Creación de nuevos brains para nuevos nichos

## 14. Qué no es MasterMind

MasterMind no es solo:

- un set de prompts
- un wrapper de LLMs
- un war room visual
- un runtime de agentes genérico
- una colección estática de brains

Es una plataforma que combina especialización, memoria, orquestación y expansión.

## 15. Posicionamiento final

> MasterMind es una plataforma de cerebros especializados que combina conocimiento destilado, aprendizaje por experiencia, orquestación experta y creación de nuevos brains para cualquier nicho, operando sobre múltiples modelos, proyectos y canales.

## 16. Decisiones canónicas resumidas

- Brains siguen siendo el core
- Agent Skills reemplaza a GSD
- Hermes es referencia runtime principal
- OpenClaw queda como referencia secundaria
- Multi-LLM es requisito estructural
- Experience Learning es pilar oficial
- Brain Factory es pilar oficial
- Expert Recommendation y Distillation son capacidades internas del producto
