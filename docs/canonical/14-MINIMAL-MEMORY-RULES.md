# Minimal Memory Rules

## 1. Objetivo

Definir las reglas mínimas para que MasterMind capture aprendizaje útil sin generar ruido, contaminación doctrinal o almacenamiento excesivo.

## 2. Principio central

> No todo debe recordarse. Solo debe persistirse lo que aumente la calidad futura de decisiones, coordinación o creación de brains.

## 3. Tipos de memoria

### A. Doctrine Memory

Conocimiento base relativamente estable:

- principios
- frameworks
- criterios de decisión
- anti-patrones

### B. Experience Memory

Aprendizaje derivado de ejecución:

- decisiones tomadas
- resultados obtenidos
- objeciones útiles
- gates que evitaron errores
- patrones emergentes

## 4. Regla crítica

La experiencia **no** debe sobreescribir doctrina base sin validación explícita.

## 5. Qué sí guardar

### Guardar siempre

- decisiones importantes
- objeciones que cambiaron el resultado
- vetos relevantes
- gates críticos
- fallos repetidos
- heurísticas que demostraron utilidad
- patrones confirmados en más de un caso

### Guardar frecuentemente

- outcomes de workflows multi-brain
- lecciones de proyectos externos
- mejoras reutilizables de plantillas o protocolos

## 6. Qué no guardar por defecto

- opiniones aisladas sin consecuencia
- análisis redundantes
- resultados no validados
- logs operacionales triviales
- ideas sin contexto ni uso potencial
- ruido repetitivo

## 7. Niveles de promoción

### Nivel 1 — Observation

Hecho aislado. Aún no es patrón.

### Nivel 2 — Pattern

Se repite en múltiples casos o contextos.

### Nivel 3 — Heuristic

Ya puede guiar decisiones futuras bajo ciertas condiciones.

### Nivel 4 — Doctrine Candidate

Solo tras suficiente validación puede proponerse como cambio doctrinal.

## 8. Reglas de promoción

### Observation → Pattern

Promover si:

- ocurrió más de una vez
- tuvo impacto real
- aparece en contextos comparables

### Pattern → Heuristic

Promover si:

- ayudó a tomar mejores decisiones
- redujo errores
- fue útil operacionalmente

### Heuristic → Doctrine Candidate

Promover solo si:

- no contradice doctrina base sin justificación fuerte
- tiene validación suficiente
- mejora calidad de forma consistente

## 9. Memoria por nivel

### Brain-local memory

Aprendizajes específicos de un brain.

### Project memory

Aprendizajes ligados a un proyecto particular.

### Core memory

Aprendizajes generalizados al framework.

## 10. Reglas de promoción al core

Un aprendizaje solo sube al core si:

- generaliza más allá de un proyecto
- es reusable
- mejora un protocolo, brain o template
- no depende de una excepción local

## 11. Qué debe guardar cada workflow multi-brain

Mínimo:

- problema
- brains participantes
- desacuerdos clave
- decisión final
- gates
- resultado / estado
- aprendizaje capturado

## 12. Riesgos a evitar

- recordar demasiado
- mezclar ruido con signal
- contaminar doctrina con experiencia débil
- no separar memoria local de reusable memory

## 13. Decisión canónica

> La memoria mínima de MasterMind debe priorizar decisiones, objeciones, gates y patrones útiles; la experiencia solo asciende de nivel cuando demuestra valor repetido y reusable.
