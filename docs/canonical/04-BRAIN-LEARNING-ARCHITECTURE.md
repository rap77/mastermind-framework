# Brain Learning Architecture

## 1. Objetivo

Definir cómo un brain aprende de su experiencia sin contaminar su doctrina base.

## 2. Principio central

Los brains no solo consultan conocimiento destilado; también deben **mejorar con experiencia validada**.

## 3. Dos memorias separadas

### A. Domain Knowledge

Conocimiento experto destilado:

- principios
- frameworks
- criterios de decisión
- anti-patrones

### B. Experience Memory

Aprendizaje operativo:

- decisiones tomadas
- resultados
- validaciones de Brain #7
- heurísticas
- errores repetidos
- patrones contextuales

## 4. Regla crítica

La doctrina base y la memoria de experiencia no deben mezclarse sin control.

## 5. Qué significa aprender

Aprender significa:

- recordar qué funcionó
- evitar errores previos
- reutilizar heurísticas validadas
- mejorar recomendaciones futuras

No significa auto-reescribir libremente el prompt base.

## 6. Condiciones para consolidar aprendizaje

Solo debe guardarse como aprendizaje fuerte aquello que sea:

- validado
- trazable
- contextualizado
- útil en más de una ocasión
- compatible con la doctrina base

## 7. Niveles de aprendizaje

### Nivel A — Observación

“Esto ocurrió”

### Nivel B — Patrón

“Esto ocurrió varias veces”

### Nivel C — Heurística

“En contexto X suele funcionar Y”

### Nivel D — Upgrade operativo

“Este brain puede usar esta heurística por defecto”

## 8. Fuentes de experiencia

- ejecuciones del brain
- feedback de Brain #7
- quality scores
- resultados de proyecto
- memoria por nicho/proyecto
- trazas de runtime relevantes

## 9. Riesgos

- aprender de outputs no validados
- mezclar ruido operacional con doctrina
- sobreajustar a un proyecto
- consolidar malas heurísticas

## 10. Decisión canónica

> MasterMind debe implementar brains aumentados por experiencia usando memoria operativa validada, separada del conocimiento doctrinal base.
