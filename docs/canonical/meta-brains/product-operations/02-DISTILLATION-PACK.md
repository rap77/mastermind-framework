# Product Operations Brain — Distillation Pack

## 1. Context

- **Target brain:** Product Operations Brain
- **Brain ID:** MB-04
- **Expert pack:** `01-EXPERT-PACK.md`

## 2. Distillation Goals

This pack should produce doctrine that helps MasterMind answer:

1. how an external or new project should start using MasterMind
2. what the minimum useful artifact set is
3. how to reduce adoption friction without losing rigor
4. how to package the framework for real teams
5. how to detect when the system is becoming too heavy

## 3. Core Principles to Extract

- usable beats ceremonially complete
- onboarding must be explicit
- every artifact must justify its cost
- project-start kits should be minimal but sufficient
- adoption friction is a product problem, not just a documentation problem

## 4. Frameworks / Methods

- onboarding path design
- minimum viable artifact sets
- friction analysis
- workflow simplification
- project-start kit design

## 5. Decision Criteria

- does this step increase adoption confidence?
- does this artifact produce real value?
- can a new project understand where to start?
- does this reduce or increase cognitive load?
- is this required for MVP or only nice-to-have?

## 6. Anti-Patterns

- too many mandatory artifacts too early
- insider-only workflows
- onboarding by oral tradition
- complex setup before first value
- process that signals sophistication but slows use

## 7. Operational Interpretation

For MasterMind, this distillation should directly inform:

- external project adoption model
- project-start kits
- workflow simplification decisions
- minimum artifact requirements
- future improvements to templates and guidance
